# MDPro3 对战布局与操作对齐

分支：`feat/mdpro3-duel-parity`，基于 `feat/mdpro3-duel-experience` 的 `9245adc`。

本分支以 MDPro3 **桌面布局**为基准，统一场地、卡片与界面坐标，保留 Neos 的配色、图标和卡图资源。竖屏等比缩放同一套场地；超宽屏按相机规则扩展，不另排区域。

## 对照来源

核对 [MDPro3 官方仓库](https://code.moenext.com/sherry_chaos/MDPro3) 的固定提交 [`e177cd8d53092ae9249e37b38d3cef0040e41095`](https://code.moenext.com/sherry_chaos/MDPro3/-/tree/e177cd8d53092ae9249e37b38d3cef0040e41095)：

- `GameCard.cs`、`CameraManager.cs`、`Main.unity`：场地坐标、相机、手牌弧度、移动与翻面。
- `OcgCoreUI.cs`、`OcgCoreUI.prefab`：生命值、说明面板、阶段锚点和五个控制按钮。
- `GenericCardList.prefab`、`CardList.cs`、`DuelLog.prefab`：右侧窗口尺寸、单列/三列排序、日志让位与恢复。
- `PopupDuelPhase.prefab`、`PopupDuelSelectCard.prefab`、`PopupDuelYesOrNo.prefab`：阶段、选卡与确认窗口的位置和尺寸。
- `DuelButton.cs`、`DuelMessage.cs`、`MessageProcessor.cs`、`ChatPanel.cs`：指令顺序、动画事件、附加效果和聊天操作。

这里只移植坐标和处理规则，没有引入 Unity、AssetBundle、模型或粒子资源。

## 布局基准

UI 以 1920×1080 为参考，横屏按高度缩放；竖屏按宽度缩放并居中。世界坐标一单位对应 20 CSS px。场地槽位、卡片、攻击落点和数值标签共享投影，避免卡图和点击区域分离。

| 区域          | 参考坐标/尺寸                                                      |
| ------------- | ------------------------------------------------------------------ |
| 相机          | 位置 `(0,95,-37)`，俯角 70°，垂直 FOV 30°；16:9 至 32:9 渐变至 33° |
| 主怪兽区      | X 为 `(-17.2,-8.6,0,8.6,17.2)`；双方 Z 为 `-9.48 / 9.51`           |
| 额外怪兽区    | X 为 `±8.6`，Z 为 0；双方镜像共享相同槽位                          |

## 操作规则

- 点击卡片先查看详情，再显示附近的合法操作；重复点击保持操作按钮打开。超量怪兽同时打开素材列表，其他卡片关闭素材列表。点击空白场地关闭说明与卡堆，并恢复被让位的日志。
- 操作顺序沿用“发动→攻击→表示形式→特殊召唤→通常召唤→盖放”；多卡/多效果先选卡、再选效果。
- 长手牌超过十张时可横向拖动，结束拖动不会误选卡或发送响应；小数量手牌恢复默认位置。
- 阶段入口只在当前玩家收到合法 idle/battle 指令、没有其他选择提示时启用。两种指令分别编码，并在发送前同步消费，防止重复发送。
- 连锁时点按钮直接循环“智能→全部→忽略”；A/S/D 分别选择全部/忽略/智能。保留浏览器 Tab 的键盘焦点导航。
- 查看卡堆时日志暂时让位，关掉卡堆恢复日志；单列与三列按源码的牌堆顺序排列。
- 附加效果按玩家位掩码去重，原始 `PLAYER_HINT` 的添加/移除分别处理；禁止查看墓地的提示即时生效。卡片记录按 UUID 跟随卡片。
- 选择窗口可用右键或 Escape 收起到场地边缘，再恢复；收起不会取消服务端选择。聊天输入中保留输入焦点，空消息确认关闭聊天。
- 菜单内提供投降确认、动画质量和自动卡片说明设置。新局与退出清除旧弹窗、手牌拖动、临时翻面、附加效果和右侧窗口状态。

## 动画处理

已有连锁、攻击、无效、召唤类型和性能降级机制继续使用，移动按照事件与原因分流。

| 情况           | 处理方式                                                                |
| -------------- | ----------------------------------------------------------------------- |
| 普通移动       | 从源姿态到目标区域，默认基准 400 ms                                     |
| 抽卡           | 从牌组姿态出发；我方 500 ms、对方 250 ms，低弧线到手牌                  |
| 进场/盖放      | 比场上平移使用更高的轨迹；到达目标表示形式再落位                        |
| 表示形式变化   | 在原槽位进行 200 ms 翻转，保留最新公开卡图                              |
| 破坏/解放/素材 | 源位置先短暂收缩/淡出，再执行对应目的区域的移动                         |
| 回牌组/额外    | 独立返回轨迹，到达后按可见性恢复卡背                                    |
| 送墓/除外      | 使用各自目标锚点与表示方向，结束后恢复透明度和高度                      |
| 衍生物         | 在目标槽位生成；消失消息先完成收缩再移除模型                            |
| 发动/确认/无效 | 临时公开卡面按动画生命周期持有；结束恢复隐藏状态，不修改隐藏的协议卡号  |
| 攻击           | `MSG_ATTACK` 只指向；`MSG_BATTLE` 执行冲击和归位，取消/伤害结束清除指向 |
| 连锁           | 编号和结算跟随实际消息，历史归入日志区域；旧定时器不能隐藏下一条连锁    |
| 生命值         | 数字短暂补间，墙钟兜底和后台切换强制落到最终值                          |

时长继续接受用户动画速度设置；减少动态效果、低性能降级、后台标签页和停帧兜底沿用基础分支。装饰动画不阻塞图片加载或规则查询，必须保留最终牌面与数值状态。

## 验证

```bash
npx tsc --noEmit
npm run lint
npm run build
./node_modules/.bin/esbuild tests/duel-pacing.test.mjs tests/mdpro3-experience.test.mjs tests/mdpro3-parity.test.mjs tests/card-animation.test.mjs tests/eventbus.test.mjs tests/local-id.test.mjs --bundle --platform=node --format=esm --out-extension:.js=.mjs --outdir=/tmp/neos-parity-tests
node --test /tmp/neos-parity-tests/*.test.mjs
npm run test:e2e -- tests/e2e/mdpro3-parity.spec.ts tests/e2e/mdpro3-duel.spec.ts tests/e2e/duel-pacing.spec.ts tests/e2e/duel-dialog-regression.spec.ts tests/e2e/adaptive-scale.spec.ts --workers=1
```

测试覆盖投影与点击区重合、画布适配、阶段合法性与回传编码、手牌拖动、时点快捷键、卡堆/日志切换、聊天、原始附加效果消息、无动画帧时 LP 落位、新局清理，以及基础分支的连锁、无效和选择回归。Neos 的 protobuf 枚举与引擎位掩码分别验证，不能混用。

核对方式为官方源码/prefab 与浏览器回归；没有运行 Unity 客户端进行逐像素截图比对，也没有测量真实网络对局或用户设备帧率。

## 部署

在服务器现有仓库目录执行：

```bash
git fetch origin
git switch feat/mdpro3-duel-parity
git pull --ff-only origin feat/mdpro3-duel-parity
docker compose up --build -d
```

端口沿用 `18080`，访问 `http://服务器IP:18080`。原实验分支仍保留，可随时切回。
